# Imported Machine Monitor behavior

This record describes the existing application being imported under dev ADR 0017. It is an import record, not evidence of GitHub CI, reviewer-App activation, installation, notarization or release. Detailed portable operating instructions and metric definitions are maintained in README.md.

## Product requirements preserved by the import

- R1: A dedicated Apple Silicon/macOS 26+ AppKit/WKWebView window bundles a local loopback metrics service. The resulting app runs independently of Codex, Python installations and browser tabs.
- R2: A fresh visible app launch starts one 30-second scan at approximately one-second intervals. The scan ends at an immutable deadline and resets its control. The user can repeat, choose 60 seconds, stop early or take a snapshot. Reloading/restoring does not automatically restart collection.
- R3: Hiding, minimizing, occlusion, lease expiry, window closure and app exit stop collection conservatively. App-owned services and subprocesses have bounded lifetimes and cleanup. No login item or background collector is installed.
- R4: Labeled interactive charts show CPU, memory, swap, disk, I/O, thermals and relevant context. Historical hover/focus updates matching process tables without shifting page layout. Responsive layouts, threshold regions and unavailable values remain explicit.
- R5: Process rows roll up each parent with its observed descendants, summing CPU, RSS, memory percentage, threads and process counts across disjoint membership. Expanded rows show individual members. PID reuse, missing parents, partial baselines and shared-page accounting are handled explicitly.
- R6: CPU/GPU temperatures use supported read-only sensor mappings when available. OS thermal state is separate from temperature. Unsupported or inaccessible sensors remain unavailable and are never replaced with fabricated values.
- R7: Health and current workload headroom scores identify partial coverage. Alerts describe disk pressure, memory pressure, thermal state, persistent CPU saturation and short-window RSS growth. Growth is an observation rather than a memory-leak diagnosis; scores do not predict task speed.
- R8: Telemetry remains local and in service memory. Loopback host checks, session cookie, same-origin checks and a custom request header protect access. Process arguments and environments are neither collected nor exposed.
- R9: Public verification uses synthetic process/metric fixtures, isolated temporary output, dynamic ports and a separate frozen fixture service. Real-device sensors, retained scans, installed applications and personal workspace paths are excluded from CI.
- R10: Six stable executable shards cover governance, core, service, browser-layout, browser-lifecycle and native-app. A complete current-invocation/current-revision evidence set is required by ci-required; missing, cancelled, skipped, failed, empty, stale and duplicate evidence fails closed.

## Delivery boundaries

The repository is public under a proprietary source-visible license with separately identified third-party notices. Standard macos-26 hosted runners use at most four concurrent shards, bounded timeouts and 14-day evidence retention. Reviewer-App source is staged: secure repository-scoped installation, owner-provisioned secrets, effective merge controls, read-only readiness and a legitimate ordinary-head canary are separate activation requirements. Protected governance, verification, workflows and packaging use the owner path.

Signed releases, notarization, updater, binary publication and replacement of the installed application are separate future work. Source validation and local device qualification do not establish those outcomes.
