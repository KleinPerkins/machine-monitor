# Private delivery and automatic updates

## Outcome

Deliver a signed, notarized Machine Monitor app for the owner and invited friends, with working automatic updates included in this session. The source repository remains public and proprietary. Downloads and update delivery are restricted to authorized recipients.

## Product requirements

- REL-001: Build qualified releases from exact merged source revisions with successful six-shard ci-required verification. Record application/build version, source revision, Apple Silicon architecture, macOS26+ minimum, pinned runtime/build dependencies and artifact checksums without retained host telemetry or private machine receipts.
- REL-002: Sign the standalone app and every nested executable with the owner-selected Developer ID, hardened runtime and secure timestamps. Distribution qualification requires strict nested signature validation, Apple notarization acceptance, a validated stapled ticket and normal Gatekeeper acceptance for the final artifact.
- REL-003: Install reversibly at the existing Applications path and bundle identifier so the Dock entry continues to work. Verify and retain the previous app before same-volume replacement and restore it on failed acceptance. Preserve the existing visible first-launch30-second scan, repeat/reset, stop, reload, hide/minimize/restore, quit and helper cleanup behavior.
- REL-004: Once update access is configured, automatically check for newer releases on launch and periodically while the app runs, authenticate downloads, verify and stage updates, and install safely when idle or at the next suitable quit/relaunch. Preserve an active metrics scan until it ends or the user stops it. Provide a manual Check for Updates action and controls to disable automatic checking or installation. Updates must not create a metrics scan or login/background collector.
- REL-005: Permit the owner to invite and revoke friends individually. Each authorized recipient can download the first app and receive automatic updates with their own access; store recipient credentials securely in macOS Keychain. Owner administration/signing credentials stay outside recipient apps and public source. Test revoked and unauthorized access for both discovery and downloads.
- REL-006: Serve the update feed and archives through an access-controlled HTTPS channel. Authenticate publisher signatures and validate app identity, expected signing team, platform compatibility and increasing build versions before installation. Tampering, wrong identity/team/platform, invalid signatures, downgrade attempts, expired/revoked access and interrupted replacement fail safely with bounded cleanup and rollback. Send access tokens only to approved update origins.
- REL-007: Keep compiled downloads private to the owner and invited friends. Include a separate personal-use permission for authorized recipients while preserving proprietary source/artwork ownership and independent third-party licenses/notices. No public binary-use grant or public release asset is implied by the public source repository.
- REL-008: Keep metrics, process inventories and scan history local. Update traffic contains only what authentication and delivery require. Update or credential failures cannot weaken the loopback session model, alter collection visibility limits or change repository merge protections.
- REL-009: Extend the existing six verification shards with meaningful synthetic update, access, feed, packaging and install fixtures and complete shard coverage. Public tests remain credential-free and independent of real inventories, sensors, installed apps and developer credentials. Actual Developer-ID/notarization and private-channel upgrade checks are separate owner-local qualification.
- REL-010: Verify an actual signed older-to-newer automatic update through the selected private channel, including recipient authentication, successful installation/relaunch and retained scan/lifetime behavior. Publish only qualified artifacts linked to reviewed merged source, version and checksums. Protected packaging, dependency, workflow and governance changes retain the owner path; they do not substitute for the separate ordinary reviewer-App approval/merge observation.

- REL-011: Private delivery must incur no subscription or hosting usage charges. Use only positively qualified Free-plan features; never activate billing, paid capacity, trial conversion or a paid/public fallback. At quota exhaustion, downloads/update checks deny access without serving private bytes, while installed local monitoring remains available. Unknown or paid account state blocks provider operations. Ask before any otherwise useful step that would introduce cost exposure; the current hard $0 decision supplies no such approval.

## Acceptance evidence

- Clean build and bundle metadata match the exact qualified revision and pinned dependencies.
- Signature, notarization, ticket, Gatekeeper, final version and artifact digest agree.
- Reversible installation preserves the Dock path and original backup; the installed native scan, reset/repeat, visibility, quit and helper cleanup checks pass.
- Owner and invited recipients can obtain the private app; unauthorized or revoked recipients cannot discover or download protected updates.
- Automatic update discovery, authenticated download, signature verification, safe installation and relaunch work end to end with an actual signed older/newer pair.
- Synthetic negative cases cover current/newer/older versions, tampering, wrong identity/team/platform, network failure, token expiry/revocation, cancellation, credential-safe redirects and rollback after interrupted replacement.
- All six shards and ci-required pass for PR head and merged source; publication and live qualification evidence remain separate.

## Boundaries

Preserve the original artifact and verified installed-app backup. Keep private keys and Apple/publishing credentials in owner-controlled secure stores. Select and record the private-channel hosting/authentication design after this requirements approval and qualify actual owner access before deployment. New repositories, if needed, inherit dev governance and mandatory sharding without expanding the controller execution boundary. Excluded repositories, paid/self-hosted runner policy and unrelated credentials remain untouched. Missing external access or release validation remains an explicit incomplete milestone.


## Free-only delivery amendment

Replace the R2 storage selection with a qualification candidate using Workers Static Assets, unconditional Worker authorization and existing current-primary D1. The former approved requirements and decisions remain frozen predecessors. All ten original requirements remain mandatory, with REL-011 added. Qualification is required before any deployment, publication or installed-upgrade claim. Provider choice remains independent of running the local monitor; no fleet migration is included.
