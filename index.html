How to read these measurements

Scores & alerts

Health is the minimum of disk, memory pressure and thermal-state factors. It is partial if a domain is missing. Disk factors: normal 100, warning 60, critical 20. Memory pressure: normal 100, warning 60, critical 20. Thermal: nominal 100, fair 85, serious 50, critical 10.

Headroom is the minimum of CPU idle %, available-memory % scaled to 100 at 35% available, native memory-pressure factor and thermal factor. It is a present-workload heuristic. GPU activity, numeric temperature and storage latency are not scored; native thermal state is scored. It cannot predict task speed.

Disk and native-state alerts apply immediately. CPU saturation must persist for the configured window; it clears after a recovery window. RSS growth above 256 MiB over ≥15 seconds produces an observation, never a confirmed leak.

Definitions & limitations

CPU rates use counter deltas over actual elapsed time. System CPU is normalized to total capacity; process CPU is normalized to one core and may exceed 100%. First observations are baselines. Load averages cover 1 / 5 / 15 minutes and are contextual counts, not CPU percentages.

Memory used here = physical total − OS available. Wired and compressed values are supporting, potentially overlapping breakdowns, not added to that total. Process memory is RSS, not private footprint; shared pages can appear in several processes. Tables roll up each parent and all observed descendants, stopping at the system launcher (PID 0/1). Each process contributes to one group. Missing parents stay separate, and independently launched processes with the same name are not merged. Expand a group for individual member metrics. Group RSS changes include membership changes, not just growth within a stable set of processes.

Swap allocation can grow dynamically. “Unused allocation” is not maximum swap capacity. Swap activity uses vm_stat counter differences. Disk throughput is aggregate device I/O; startup capacity represents the shared APFS pool once. GPU driver counters are best-effort diagnostics; GPU memory shares physical RAM.

Collection is ~1s for core metrics; GPU and power are ~5s, with their age displayed. Abrupt closure expires a 3s backend lease; in-flight sensor commands have a 0.6s timeout. Results remain in this running service only. Reopening does not resume collection.

Sources: psutil 7.2.2, macOS sysctl / vm_stat, IORegistry driver counters, and NSProcessInfo thermal state. CPU/GPU temperature averages and maxima use read-only SMC sensor readings and a verified M2-family key mapping. Missing, zero and invalid readings stay unavailable. The hottest reported value is the hottest mapped sensor, not a guaranteed junction hotspot. Temperature warnings use native macOS thermal state, not an invented universal °C limit. No latency benchmark or reliable per-process disk/GPU attribution is provided.
